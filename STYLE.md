# STYLE.md

My voice guide for FJDEV. Drafts follow it. If a draft sounds like a press release, it fails.

## Audience and voice

I write for peers: developers and engineers working with Terraform, Azure and AI, in English, internationally.

FJDEV is the field view of infrastructure as code on Azure, done like a developer. Three layers: Terraform and Azure Verified Modules, delivery with GitHub and Azure DevOps, and AI that helps write better infrastructure code.

- I write in first person, plainly and directly. Short sentences.
- I start from something I ran into, built or think. Not from the news.
- I say what worked, what did not, and what I would do differently.
- I stay understated. No hype, no sales tone, no claims I cannot back up.
- Every post starts from my own words. Claude never invents experiences, numbers or quotes. If the material is thin, ask me. Do not pad.

Do / don't:

| Don't | Do |
|---|---|
| "This game-changer transforms your workflow." | "This saved me an afternoon on a refactor." |
| "Let's dive into the world of modules." | "I hit a problem with a module last week." |
| "Terraform 2.0 introduces many features." | "The new provider version changes how my existing state behaves. Here is what I checked." |
| "It is widely known that workspaces are bad." | "I stopped using workspaces for environments. Here is why." |

Banned words and phrases: game-changer, unlock, leverage, seamless, robust, delve, dive in, "in today's fast-paced world", "revolutionize", "supercharge", "best practices" as a filler, "excited to announce".

## Content formats

| Type | Format | Words |
|---|---|---|
| how-to | Post. One task, steps that worked. | 300-600 |
| release-take | Post, short. Always my view on what it means in practice. Never a plain news rewrite. | 300-600 |
| exam-notes | Post. How I prepared and what I would do differently. Preparation and experience only. | 300-600 |
| opinion | Post. One point. | 300-600 |
| snippet | A code block plus 2-3 sentences. | no minimum |

Word counts for posts exclude code blocks.

## Anti-goals

- Posts that read as AI-written or as generic news rewrites.
- Polished corporate copy, even if it would get clicks.
- Anything that blurs FJDEV with my employer.
- Topics outside my own interests, written for reach.
- Long tutorials. One point per post.

## Client and NDA rules

- No client names, internal code or engagement details. Generalise every example.
- Exam notes cover preparation and experience only. Never exam content or questions.
- Never mention my employer as if I speak for it. These are my views.
- No company secrets. When unsure, leave it out and ask me.
